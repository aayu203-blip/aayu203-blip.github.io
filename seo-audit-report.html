MEDIUM Bespoke page H1 rendered by JavaScript — not in raw static HTML

Pages like 23715461 and 22717828 build their H1 via window.PTC_CUSTOM_HERO() JavaScript. The static HTML source contains only <div id="root"></div>. While JSON-LD schema and canonical tags are in the static <head>, Googlebot must render JS to read the actual H1. Google's indexing pipeline handles this but introduces a crawl-latency risk.   • Recommendation: Add a static <h1> in the HTML body (can be visually hidden with CSS if needed for design) so the part number is indexable without JS execution.

  • All bespoke pages: use pattern {partNo}-{brand}-{partName}-{angle}.webp — already done for clutch plate and hollow spring.
  • Catalog pages: at minimum, rename the generic image or use an image-level og:image with the part number in the URL.

SECTION 09

Duplicate Template Risk

Template duplication analysis across catalog product pages

HIGH Catalog pages share identical description template — only part number and model list differ

All catalog pages (30,000+) use a template-generated description block:

"OEM-specification {partName}. Part number {partNo}. Compatible with: {modelList}. Supplied by Parts Trading Company, Mumbai. Est. 1956. Ships worldwide."

The categoryDesc field in the JS data object is also template-fill:

"Volvo Bearing & Bushing from Parts Trading Company cover the full range of Volvo equipment. We supply OEM-specification aftermarket bearing & bushing sourced from certified manufacturers. PTC has supplied Volvo bearing & bushing to customers across India, UAE, Russia, Indonesia, and Africa since 1956. Our Mumbai warehouse stocks high-turnover Volvo bearing & bushing for same-day dispatch before 3 PM IST."

This is near-identical across all catalog pages within a category — only the category name changes. With 30,000 pages sharing structural content, Google's duplicate content filters may aggressively thin the index to only the most authoritative (bespoke) pages.

  • Enrich catalog page descriptions with the part's specific technical function, at least 1 unique sentence
  • Even a simple template variant using partType and primaryModel would differentiate pages
  • Priority: enrich top 500 highest-traffic catalog pages first
MEDIUM FAQ questions are identical across all catalog pages — 4 stock questions reused

Sampled catalog page 11000274 has FAQ array: "Is this part compatible with my machine?", "Is this OEM or aftermarket?", "How quickly can this part be dispatched?", "Do you export internationally?" — these 4 questions appear verbatim on every catalog page. While this is in the JS faq array rather than in FAQPage schema, if FAQPage schema is added to catalog pages, identical FAQs across 30,000 pages would likely suppress rich result eligibility.

SECTION 11

Orphan Pages + Crawlability

Sitemap coverage, navigation reachability, redirect-layer orphans

HIGH 52,695 /products/{partNo}.html redirect files — no nav links to these URLs

The /products/ directory contains 52,695 HTML files using meta http-equiv="refresh" to redirect to canonical brand/category/partNo URLs. These redirect pages have canonical tags pointing to the final destination and no nav links anywhere on the site. They are de-facto orphan pages — reachable only via direct URL or if linked from external sources using the old URL pattern.

  • These pages do not appear to be included in the main sitemaps (sitemap-main.xml, sitemap-volvo.xml etc.) — the sitemaps correctly list canonical brand/category/partNo URLs
  • If any external links or old bookmarks point to /products/ URLs, the meta refresh redirect (not a 301) passes less link equity than a server-side redirect
  • Recommend: verify whether /products/ URLs are being indexed via Google Search Console. If indexed, these are wasted crawl budget
  • The meta refresh redirect is functionally a 0-second soft redirect. Google treats it similarly to a 301 but with less certainty. If the server supports it, implement 301 redirects via _redirects or .htaccess instead
MEDIUM New-products sitemap URLs (komatsu/spare-parts/PC210, komatsu/engine-parts/14Y-50-00010) — structure differs from main catalog pattern

sitemap-new-products-1.xml contains URLs like https://partstrading.com/komatsu/spare-parts/PC210 and https://partstrading.com/komatsu/engine-parts/14Y-50-00010. These have priority 0.8 but their URL pattern differs from the main catalog (which uses only numeric part numbers). "PC210" is a machine model, not a part number — this may produce a model-level page rather than a product page. These need verification that they return 200 and have appropriate content.

PASS All sampled canonical product pages reachable via brand → category → product URL path

The hierarchy volvo/ → volvo/transmission-parts/ → volvo/transmission-parts/23715461 is structurally sound. Each level has internal links to the next. Sitemaps correctly list all three levels. Brand index pages include category links in static HTML for crawl discovery without JS.
